## 1. 목표와 방법

Superpowers의 문제 재현 → 회귀 테스트 작성 → 수정 → 실제 빌드 및 검증 순서로 진행했다. 원본 파일은 SHA-256으로 고정하고, 편집 테스트는 임시 복사본을 사용했다. ZIP/XML 구조 비교, PDF의 페이지·필드·위젯 분석, 화면에서 동작하는 Electron Playwright 테스트를 조합했다. 수동 추측이나 테스트를 건너뛴 결과는 성공으로 표시하지 않았다.

**총 713개 Vitest 통과**, `tools/qa/` Node 테스트 **13개 통과**. 실제 Electron 화면 E2E **14개 통과**. 정식 기준 보고서와 원시 로그는 `baseline-20261028-230813.md` 및 `logs/`에 있다. 전체 워크스페이스 TypeScript 검사 및 HWP·셸 빌드도 통과했다. E2E는 이 프로그램 내부의 동작을 검증하며 외부 공급사 프로그램의 저장 호환성을 증명하지 않는다.

## 2. 새로 발견하고 차단한 위험

### HWPX 마스터페이지의 무단 재작성

처음 작성한 E2E는 아무 변경도 없는 문서에서 저장 이벤트만 보내고 실제 파일 쓰기를 기대하여 시간 초과됐다. 앱이 정상적으로 무변경 저장을 생략한다는 점을 확인하고, 마스터페이지가 있는 실제 HWPX 문서의 **임시 복사본 본문에 글자를 입력**하도록 수정했다.

저장 결과의 원본 대비 구조 검사에서 `Contents/masterpage0.xml`과 `Contents/header.xml`이 바뀐 것을 발견했다. 구체적으로 마스터페이지 문단 ID가 다시 부여되고 빈 텍스트 요소가 사라졌으며, 헤더의 기존 문단 `textDir` 속성 등이 누락됐다. 파일이 압축 해제되고 마스터페이지 파일이 존재한다는 사실만으로 안전하다고 판정할 수 없다.

`apps/hwp/src/main/hwpx-save-validation.ts`에서 원본 HWPX의 **마스터페이지 XML 바이트가 동일하게 유지되지 않으면 저장 전 중단**하도록 강화했다. HWPX ZIP CRC, XML 구문, 필수 멤버, 기존 섹션/내장 파일 존재 검사 및 메모 손실 검사는 계속 적용된다. 실제 Electron E2E에서 이 위험 문서의 수정 후 저장은 `blocked`로 종료됐고 **원본 해시 유지 및 불필요한 백업 생성 없음**이 확인됐다. 바탕쪽을 수정하는 안전한 편집기는 현재 제공하지 못하므로 해당 문서의 쓰기는 제한된다.

### 기타 안전성 수정

- HWP 복원할 수 없는 section-tail/메모를 감지하면 원본을 대체하기 전에 중단한다.
- HWPX 원본 메모 및 내보내기 결과의 파싱·개수 확인이 실패하면 무손실이라고 추정하지 않고 저장을 중단한다. 자동 저장에도 적용한다.
- PDF 비동기 양식 저장 E2E는 실제 디스크 반영과 UI 갱신을 모두 기다려 거짓 실패를 없앴다.
- 기존 HWP 파일 충돌 테스트에서 HWPX의 불완전한 가짜 데이터를 사용한 오류를 형식에 맞게 고쳤다.

## 3. 출시 판정 및 남은 증거

| 검증 항목                            | 상태        | 이유                                                                           |
| ------------------------------------ | ----------- | ------------------------------------------------------------------------------ |
| 로컬 테스트·Electron 테스트·빌드     | **PASS**    | 새 검사와 실제 UI 저장 흐름 확인                                               |
| HWP 구조적 무손실 검증               | **LIMITED** | OLE 컨테이너의 서명 검사 외에 독립적인 전체 개체 비교 없음                     |
| HWPX 복잡 문서 외부 저장·재열기      | **BLOCK**   | 기존 6건의 한컴 2024 재열기 실패가 재검증되지 않음; 마스터페이지 재작성도 확인 |
| DOCX의 Word/LibreOffice 재열기       | **NOT RUN** | 별도 실제 편집기 검증 자료 없음                                                |
| XLSX의 Excel/LibreOffice 재열기      | **NOT RUN** | 복잡한 차트·수식·매크로 등 공급사 재열기 필요                                  |
| PPTX의 PowerPoint/LibreOffice 재열기 | **NOT RUN** | 슬라이드·글꼴·미디어 렌더링 검증 필요                                          |
| PDF의 독립 뷰어 시각 비교            | **NOT RUN** | 내부 구조 및 UI 동작은 확인, 타사 렌더러는 미확인                              |
| 실구독 Codex/Claude 자연어 명령      | **NOT RUN** | `TTOK_AGENT_REAL`을 명시적으로 활성화하지 않음; 실제 문서 전송 없음            |

`tools/qa/release-gate.mjs`의 전체 편집 출시 판정은 **BLOCKED**다. 이 결정은 **보고서 수준의 품질 게이트**이며, 모든 앱의 쓰기를 일괄 비활성화하는 런타임 기능이 아니다. 실제 사전 쓰기 차단은 현재 HWP/HWPX 무결성 경로에 구현됐다. 따라서 현재 자동화 통과를 근거로 '어떤 문서든 AI가 안전하게 편집한다'거나 '100% 호환'이라고 홍보하면 안 된다.

## 4. 출시에 앞서 반드시 필요한 검증

1. 이전에 한컴 한글 2024에서 열리지 않았던 HWPX 원본 **6종과 실패한 출력물**을 버전 관리용 테스트 원장으로 확보한다. 한컴 정식 편집기에서 수정·재열기·개체/서식 비교 후 재현 원인별 수정과 회귀 테스트를 수행한다.
2. Word, Excel, PowerPoint, 한컴 한글 2024, 별도 PDF 렌더러에서 **임시 테스트 사본**을 편집·저장·재열기하고 페이지, 주석, 마스터, 수식, 서식, 그림을 비교한다.
3. 실구독 AI 테스트는 사용자 명시적 연결과 파일 전송 범위 확인 후 합성 문서로 실행한다. 요청/응답, 비용, 편집 명령, 전후 해시, 실행 취소 및 재열기를 기록한다.
4. 각 형식별 P0 차단 사례가 해소되어야 품질 게이트를 PASS로 바꾼다. 이 게이트를 실제 배포 제어에 연결하는 작업도 별도로 필요하다.

## 5. 재실행

```sh
cd program
node --test tools/qa/*.test.mjs
bash tools/qa/run-baseline.sh

```

각 형식의 기준 결과·오류를 별도 로그 파일에 저장한다. 전체 검증은 문서마다 원본을 덮어쓰지 않고 새 파일에서 수행한다. 미실행된 공급사 프로그램 검사 또는 실구독 호출은 PASS로 간주하지 않는다.
